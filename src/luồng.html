🛠️ Các bước thực hiện

  • Backend (server/index.js): Tạo file SQLite myreads.db. Viết API GET /api/books và nạp 12 cuốn sách mẫu.
  • Frontend (api.ts): Viết hàm getBooks() để gọi API từ Backend.
  • Frontend (App.tsx): Dùng useEffect gọi getBooks() khi vừa mở web. Tạo State const [books, setBooks] = useState<Book[]>([]) để lưu trữ dữ liệu toàn cục.

⚙️ Logic Kỹ Thuật (App.tsx & API)
Khi user chọn kệ mới, thẻ <Book /> gọi hàm onShelfChange(id, newShelf).
Tại App.tsx, hàm handleShelfChange sẽ chạy:
  • Optimistic UI: Dùng .map() cập nhật ngay mảng books trong State để giao diện đổi kệ lập tức.
  • Gọi API: Gửi PUT /api/books xuống Backend Express để lưu vào Database SQLite.

🛠️ Các bước triển khai chi tiết

  • Hiển thị 3 kệ sách: Tạo component MainPage.tsx nhận prop books. Tạo mảng cấu hình 3 kệ. Dùng shelves.map() để vẽ kệ, dùng books.filter() để lấy sách cho từng kệ. Dùng CSS Grid để dàn trang.
  • Tạo nút chọn kệ: Trong Book.tsx, tạo thẻ <select>. Gắn sự kiện onChange gọi hàm onShelfChange(book.id, newShelf). Truyền hàm này từ App -> MainPage -> BookShelf -> Book.
  • Xử lý đổi kệ (Optimistic UI): Trong App.tsx, viết hàm handleShelfChange. Dùng setBooks với .map() để đổi kệ lập tức. Sau đó gọi updateBookShelf() để lưu vào DB. Nếu lỗi, gọi lại getBooks().

⏱️ Logic Kỹ Thuật (Debounce & Merge State)
1. Debounce: Khi gõ, dùng setTimeout đợi 300ms. Nếu tiếp tục gõ, clearTimeout hủy lệnh cũ. Ngừng gõ mới gọi GET /api/books?q=harry.
2. Đồng bộ kệ sách: Sách trả về từ API không có kệ. Code phải đối chiếu (merge) với mảng books tổng ở App. Nếu sách đã có trong thư viện, Dropdown hiển thị đúng kệ hiện tại (VD: ✅ Đã đọc).

🛠️ Các bước triển khai chi tiết

  • Cấu hình Router: Cài react-router-dom. Cấu hình 2 đường dẫn: / (MainPage) và /search (SearchResultsPage). Đặt SearchBar trong App.tsx để hiển thị toàn cục.
  • Debounce: Trong SearchBar.tsx, dùng State query. Dùng useEffect theo dõi query. Nếu gõ >= 2 chữ, dùng setTimeout 300ms, nếu gõ tiếp thì clearTimeout. Nếu ngừng gõ, gọi navigate('/search?q=' + query).
  • Hiển thị & Đồng bộ: Trong SearchResultsPage.tsx, dùng useSearchParams lấy chữ q. Gọi API getBooks(q). Lấy kết quả merge với mảng books tổng ở App để gán đúng thuộc tính shelf nếu sách đã có trong thư viện.

🛡️ Logic Kỹ Thuật (FileReader & Inline Form)
1. Form Sửa Inline: Khi bấm "Sửa", state editingBook lưu ID cuốn sách. Dùng React.Fragment chèn một dòng <tr> mới có colSpan={5} ngay bên dưới cuốn sách đó, chứa component <AdminBookForm />.
2. Upload ảnh Base64: Thẻ <input type="file"> kích hoạt FileReader. Nó đọc file từ máy tính và chuyển thành chuỗi ký tự Base64 khổng lồ (VD: data:image/png;base64,...) để lưu thẳng vào cột thumbnail của SQLite.
3. Gọi API: POST /api/books (Thêm) | PUT /api/books/:id (Sửa) | DELETE /api/books/:id (Xóa).

🛠️ Các bước triển khai chi tiết

  • Upload ảnh (Base64): Trong AdminBookForm.tsx, thêm thẻ <input type="file">. Dùng FileReader đọc file, khi có kết quả (onloadend) lưu chuỗi Base64 vào State thumbnail. Nhớ cấu hình Backend: express.json({ limit: '50mb' }).
  • Form Sửa Inline: Trong AdminPage.tsx, tạo State editingBook. Duyệt mảng books vẽ bảng. Khi bấm "Sửa", gán setEditingBook(book). Ngay dưới thẻ <tr> thông tin, thêm điều kiện: Nếu editingBook.id === book.id, chèn thẻ <tr> mới dùng <td colSpan={5}> chứa <AdminBookForm />.
  • Gọi API CRUD: Thêm: POST /api/books, cập nhật State setBooks([...prev, newBook]). Sửa: PUT /api/books/:id, đóng Form, tải lại danh sách. Xóa: DELETE /api/books/:id, cập nhật State setBooks(prev.filter(b => b.id !== id)).
